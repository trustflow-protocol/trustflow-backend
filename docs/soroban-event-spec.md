# Soroban Event Specification — TrustFlow Contract

**Issue:** #463 - Confirm Soroban event topics, value decoding, and escrow ID format

## Overview

The backend's `SorobanEventIndexerService` and `EventProcessorService` consume Soroban contract events emitted by `trustflow-contract`. This document specifies the expected event schema and format the backend relies on.

## Event Topics and Types

Events are indexed by their first topic (`topic[0]`), which encodes the event type as a Soroban symbol:

| Event Type | Topic[0] | Topic[1] | Topic[2+] | Use Case |
|------------|----------|----------|-----------|----------|
| `escrow_created` | `"escrow_created"` | — | — | Emitted when escrow is created on-chain |
| `escrow_funded` | `"escrow_funded"` | Escrow ID | — | Emitted when funds are locked in escrow |
| `escrow_released` | `"escrow_released"` | Escrow ID | — | Emitted when beneficiary releases escrow |
| `escrow_disputed` | `"escrow_disputed"` | Escrow ID | — | Emitted when escrow enters dispute |

## Value Encoding

All event values are encoded as `scvBytes` (Soroban Contract Value bytes) and must be JSON-parseable after decoding.

### escrow_created Value

```json
{
  "depositor": "<stellar-account-id>",
  "beneficiary": "<stellar-account-id>",
  "amount": "<stroops-as-string>"
}
```

**Invariants:**
- Both `depositor` and `beneficiary` must be valid Stellar account IDs (starting with `G`)
- `amount` must be a stringified integer representing stroops

### escrow_funded / escrow_released / escrow_disputed Value

For these state-transition events, the value format depends on the specific contract implementation. The backend currently expects it to be convertible to a string.

For `escrow_disputed`, an additional `reason` field may be present in the value:

```json
{
  "reason": "<optional-dispute-reason>"
}
```

## Escrow ID Format

The escrow ID is expected to be:
- **Location:** Second topic (`topic[1]`) for funded/released/disputed events
- **Format:** A string identifier that matches the contract's escrow ID representation
- **Usage:** Used to correlate on-chain events with off-chain escrow records in the database

**Current assumption:** The escrow ID is a unique, deterministic identifier generated by the contract (e.g., hash-based or sequential).

## Decoding Pipeline

1. **Topic Parsing** (`parseTopic`):
   - If `topic` is an `scvSymbol`, decode to string
   - If `topic` is `scvBytes`, decode to UTF-8 string
   - Otherwise, stringify the topic

2. **Value Parsing** (`parseValue`):
   - If `value` is an `scvBytes`, decode to UTF-8 and JSON-parse
   - Otherwise, stringify the value
